# Match 4 — web retrieval preparation

The public event page lists Intelligent Web Information Retrieval as live through October 27. Its detailed-brief link currently leads back to the event page, and the existing submission form exposes only the Match 2 and 3 image fields. The official Match 4 interface and submission route are still needed.

Implemented so far: a structure-aware page reader, bounded asynchronous navigation/evidence core, real HTTP fetching and a resident model decision adapter. The 30 CPU tests include actual local HTTP navigation, redirect provenance, charset/plain-text preservation, compressed response limits, network timeouts, late-page retrieval and independent model/tool control flow. Navigation actions take priority over partial answers, and generation retains time for the total agent deadline. These are processing/control-flow tests, not end-to-end model accuracy results.

The reader preserves table row relationships and JSON-LD values, excludes hidden decoy elements and executable script contents, resolves ordinary and HTML-base-relative links, excludes non-HTTP navigation targets, and retains phone/email values contained in link attributes. Navigation enforces a total timeout and page cap, follows only supplied or discovered HTTP(S) links, and verifies answers against pages actually read. The model receives bounded relevant passages and real unvisited links; invalid or incomplete model JSON cannot become an action. Static HTML/plain-text fetching is supported; JavaScript rendering and an independent search backend are not implemented.
